01The boundary: three owners, twelve lines

The plan's checklist reads as one list, which hides the fact that its lines close in three different ways. Four are already closed by machinery that runs without anyone asking. Six close inside this pull request. Two need a human with a browser and a microphone — and no amount of test coverage will move them across.

automated — closes on merge this PR — closes with a test human — closes with a procedure

02The failure fan: five ways one README lies

A README does not rot all at once. It rots one sentence at a time, and every one of the five ways below is already present on main at b834b61. The fan below traces each from the change that caused it to the moment a reviewer hits it — and to the check that turns that moment into a red test instead.

03The hazard: the second seed run

Seeding is a chore that gets run twice — once when it is written, once an hour before the recording, because a contact got deleted or the calendar changed. The first run is trivial. The second is the whole design problem, and the obvious fix for it (search for what exists, then create what does not) hangs the script's correctness on /contacts/search's filter grammar — the one call HIGHLEVEL_PLATFORM.md flags as least verified. So the script does not search.

04Where this slice's risk lives

Every acceptance criterion is L1, and no slice before this one could say that. It is not a gap in coverage — it is what the slice is. Nothing here runs in a browser or crosses a network, so the failure mode is never a race; it is a file that says something untrue. What no L1 can reach is drawn beside it, at its real size.

05The only new wire calls

This slice adds no Genesis endpoint. The seed script is its only new caller of anything, and it talks to HighLevel directly — not through the proxy, which deliberately does not allowlist appointment creation (Slice 8, D4), and not through Firestore, which it never touches.
