Slice 07 — Monaco editor

Spec F6.3, F6.5 · Branch slice/07-monaco-editor · Depends on 6 · Date 2026-08-18 · design companion to 02-prd.md

The demo Send a prompt, watch syntax-coloured HTML stream into a locked Monaco editor line by line; when it finishes, open a second file in a second tab, type into it, switch tabs and back to find the edit still there, save it, and reload.

01 What is actually in the box

Monaco is not one dependency, it is a menu. Three of this slice's decisions are about what we decline: the CDN the package reaches for by default (D2), the language services that would put red squiggles on generated code (D3), and every language but four (D3). What is left is one worker and one chunk.

02 The hazard: how a chunk reaches the screen

One decision in this slice is worth more than the rest combined, and it is invisible everywhere we normally look. jsdom computes no layout and runs no Monaco, so both halves of the comparison below pass every L1 and L2 test in this repository. The difference only exists in a browser, in front of a person.

03 A generation, end to end, with the model's lifecycle

The lifecycle is the part prose hides: a model is created, appended to, its view state saved when the user switches away, and disposed when the project closes. Miss the last step and two projects share one index.html — see figure 4.

04 Why the model registry is ours

The wrapper will manage models for you if you bind its path prop. Read from its source rather than its README: it keys them by Uri.parse(path) in monaco's global registry, and at unmount disposes only whichever model happened to be active. Every generated app has an index.html.

05 One panel, six exits

Every state the code panel can be in, and the sentence the user reads there. The editor now has a loading state and a failure state of its own — Monaco arrives in a separate chunk, so "the editor has not appeared yet" is a real thing that happens on a slow connection, and it must not look like an empty file.

06 Where the risk lives

Thirty-one acceptance criteria, and their distribution is itself a decision. Monaco cannot run in jsdom, so everything that can be made a pure function was, and the browser is asked to prove only the two things that need a layout engine.

07 The server surface, for the avoidance of doubt

The whole slice is frontend/ plus two e2e files. These three routes and the stream protocol are exactly what Slice 6 shipped; what changes is only when the browser calls them.

GET
/api/projects/:projectId/files
unchanged

Still one call per project open, and one more after a generation that wrote files.

GET
/api/projects/:projectId/files/:path
same shape, new cadence

One per tab opened for the first time. Re-activating a tab, or reopening a closed one, issues nothing (D10, D12). After a generation: one per open tab it rewrote, not one for the selection (D15).

PUT
/api/projects/:projectId/files/:path
unchanged

Attested, last-write-wins, scoped to the active tab. Refused while a stream is open.

POST
/generate
unchanged

token · file_start · file_chunk · file_end · done · error. This slice consumes the same frames into a different widget.

No new collection, no rules change, no index change, no system-prompt change, no configuration. The definition of done asks the review to check that against the diff rather than against this sentence.

08 Risks

# Risk Mitigation
R1 setValue per chunk instead of an append. Passes everything below L5; in the app it pins the viewport to line 1 for a whole generation. Figure 2's pure function, five ACs, and AC-10's negative — no setValue for a file while it streams. Watched at L5.
R2 The mandated wrapper is old — vue-demi, and a .d.ts that imports a monaco path current monaco no longer resolves. monaco pinned to 0.52.2; typecheck is the gate. If it still fails, stop and write it down — replacing a brief-named package is a recorded decision, not a keyboard call.
R3 Monaco cannot run in jsdom, so its visible behaviour has one proof, at L5. Figure 6: everything decidable is pure and L1. L2 asserts props against a stub.
R4 Layout collapse — Monaco measures its container, and one with no definite height renders 0 px with no error. The Slice 6 finding, in a louder form. The cap on the element that scrolls, a definite height below it, automaticLayout: true, and AC-30's non-zero height at L5.
R5 Model URI collision across projects — figure 4. Project-scoped URIs, our own registry, disposal on close. AC-6, AC-7, AC-9.
R6 Bundle weight — about a megabyte gzipped, paid for on the sign-in page. Dynamic import behind the workspace; a bundle check in the definition of done.
R7 Slice 7 is first on the cut list and the graded chain (8 → 9 → 10) is still ahead. The cut is pre-decided: revert the two dependencies and FileEditor.vue to the textarea — one commit, because every rule lives in the store and nothing on the server depends on this slice.
R8 The existing e2e drives a textarea and breaks by construction; the tempting fix is to loosen it. Updated in the same commit, through two named helpers, assertions unchanged. Weakening a test for a green suite is out of bounds here regardless.
