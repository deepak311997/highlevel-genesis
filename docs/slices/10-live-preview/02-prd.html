The sealed room

The preview runs code an LLM wrote, over a real business's CRM, inside a document that has no origin, no session, no storage and no way to open a connection. This page draws the four things the PRD can only describe: what the glass keeps out, how one call actually travels, the one race that a frame identity check cannot catch, and where every failure lands. The acceptance criteria and the test matrix stay in 02-prd.md, which is the contract.

01 What the glass keeps out

Everything in this slice follows from one fact: a srcdoc iframe has an opaque origin. It cannot read our session, its fetch arrives at the API as Origin: null, and it cannot produce an App Check attestation. So the decision (D2) is not which credential to hand it — it is to hand it none, and let our own page make every call on its behalf.

02 One generation, one call, end to end

The demo is a single pass through this. Note where the document is created and where the previous one dies — the preview's whole lifecycle is one line of it, and it is what section 03 turns on.

03 The hazard: a dead document that is still talking

The obvious way to authenticate a message from the frame is event.source === iframe.contentWindow. It is necessary and it is not sufficient — a WindowProxy survives navigation, and writing srcdoc again is a navigation. So the old document and the new one present the same identity. Left there, a request posted by build N−1 a millisecond before it died is indistinguishable from one posted by build N.

04 Where every failure lands

F8.3 asks for HighLevel failures surfaced clearly in the preview. The generated app's own try/catch is the one thing here we cannot rely on — it is model output — so the guarantee lives on the host, which sees every failure whether the app handled it or not (D17).

05 The contract, as cards

No HTTP contract changes in this slice. The one new contract is the message protocol across the glass — and the acceptance rules under it, which are the security half.

frame → host a CRM call

{ genesis: 'preview', v: 1,
  nonce: string,
  id:    string,
  kind:  'hl',
  method:'GET'|'POST'|'PUT',
  path:  string,
  payload?: unknown }

Posted with '*'. The path is model output, so it is re-checked against the same grammar the server matches on.

frame → host something broke

{ genesis: 'preview', v: 1,
  nonce: string,
  kind:  'error',
  message: string }

Uncaught throws, unhandled rejections, CSP violations and the spent call budget all arrive here.

host → frame the answer

{ genesis: 'preview-host', v: 1,
  nonce, id, ok: true,
  data: unknown }

{ …, ok: false,
  error: { message, status, code? } }

HighLevel's body, unwrapped — Slice 9's prompt carries recorded payloads as examples, so re-shaping one would make them lies.

host accepted only if

event.source === frame.contentWindow
genesis === 'preview' && v === 1
nonce === currentBuildNonce
id is a non-empty string
method ∈ { GET, POST, PUT }
path is a string

Anything else is dropped in silence: no reply, no HighLevel call. A reply never carries a token, a uid or a location id.

06 Where this slice puts its risk

Thirty-nine acceptance criteria, and the shape of their distribution is itself a decision: almost everything here is pure enough to test as a function, because the parts that are not — a real browser running real generated code — can only be proven once, at L5.

#RiskWhat holds it
R1Playwright may not read inside a sandboxed srcdoc frame — where AC-39's evidence livesIt drives frames over CDP, so an opaque origin should be reachable; the named fallback is host-visible evidence plus the hand-check in the definition of done
R2The shim is a string, so nothing typechecks itEvaluated for real in eight L1 cases with stubbed globals, and executed in a browser at L5; its surface is three globals and one function
R3Generated code can hang the tab — the sandbox does not stop a busy loopOut of scope and said so; the version of it that costs money is capped at 50 calls
R4</script> inside generated JS would corrupt the document — rare, catastrophic, invisibleMade unrepresentable rather than unlikely: content is carried as data and installed through the DOM, never parsed as markup
R5Every rebuild re-spends the CRM rate-limit budgetExactly two triggers, both deliberate; a save gets a hint, not a rebuild
R6Replies must be posted to '*' — an opaque origin has no nameReplies carry response bodies and error text only; the nonce and source checks mean a document that is not ours is never answered
R7No allow-same-origin means storage APIs throw inside generated codeThe throw is caught by the error channel and shown, so it fails loudly; a prompt line is a Slice 12 note
R8CRM data rendered by generated code is an XSS sinkContained by construction — no origin, no credential, no storage; worst case is a defaced preview of the user's own data
R9A large PR: four new modules, a rewritten panel, a shared error-path changeThe shared change is three additive call sites; there is no server surface at all, and the only honest split has an undemoable first half

07 What deliberately does not move

Worth stating as loudly as what does. The proxy, the allowlist, the error envelope and the system prompt are all upstream of this slice, and the shim's job is to match them exactly rather than extend them.

  • No Firestore change — no collection, no field, no index, no rules edit.
  • No functions/ change — no route, no schema, no allowlist row, no prompt text. hlKnowledge.ts is untouched.
  • No new dependency — the brief offers Sandpack and WebContainers; srcdoc costs nothing and controls everything.
  • No new environment variable, so .env.example is unchanged.
  • hl()'s contract is now implemented twice — once as prose in the system prompt, once as code in the shim. Neither may move without the other; hl( is the seam.
