Change what changed

Today a follow-up prompt can decide which files to rewrite, but not which lines. Adding one theme re-emits eight kilobytes of stylesheet to change forty lines — billed at output rates, generated serially, and reconstructed from context every time. This slice gives the model a located change, and reshapes the request so the parts that did not change are not paid for twice.

64% cheaper per follow-up turn
8.75× fewer output tokens
2 cache breakpoints, of 4
0 new collections, rules, indexes
The bill

Where the money actually goes

On claude-opus-5 output is five times the price of input — $25 against $5 per million tokens — and a cache read is a tenth of input, $0.50. Those three rates decide everything below.

Take a real project after turn one: index.html 6 KB, styles.css 8 KB, app.js 14 KB — 28 KB, about 7,000 tokens. Turn two is “add a dark theme.” Today the model answers by re-emitting two whole files. The re-emitted bytes are the largest single line on the bill, and because output is generated serially where input is processed in parallel, they are also almost all of the minute the user spends watching.

The case this was built for

A 100 KB file rewritten to change ten lines is 25,000 output tokens — sixty-three cents and several minutes of streaming. The same change as an edit is about 400 tokens. The saving is not uniform; it scales with how much of the file the user did not ask about.

The prefix

Why the transcript was never cacheable

Prompt caching matches a prefix, and the prefix is ordered tools → system → messages. A change at any level invalidates that level and everything after it.

The project's files go into the request as a system block, appended after the cache_control breakpoint so they do not invalidate the cheat-sheet above them. That was the right call for the system prompt and it has a consequence nobody wrote down: the block changes on every turn that writes a file — which is most turns — and it sits in front of the entire conversation. No breakpoint anywhere in messages can ever hit while it is there.

Moving it past the transcript, to the tail of the final user message, costs nothing — documents-before-query is the recommended placement for long context anyway — and it makes the conversation cacheable for the first time. buildContext already drops trailing assistant turns, so the last assistant message is the second-to-last message: the last block that is byte-identical between consecutive turns, and exactly where the breakpoint belongs.

Two breakpoints of the four allowed, and the 1-hour TTL goes on the system prompt only: 2,000 tokens that never change, where a 2× write premium is four tenths of a cent an hour and a user who thinks for six minutes should not repay it. Mixed TTLs are legal in this order — 1-hour entries must precede 5-minute ones, and system precedes messages.

One smaller change rides along for the same reason. projectState.ts orders files by ascending length so the most complete files fit the budget — which means a file that grows past its neighbour reorders the block, and a change to app.js moves styles.css's bytes. Selection stays by size; rendering becomes stable — index.html, then path.

Prior art

Five ways this has been solved, and what we take from each

None of this is invented. The format below is chosen against what the field already knows — and against one fact specific to us: our model is claude-opus-5, so the shape it was trained on is a real argument.

System Format Matching What we take
Anthropic text editor tool

It solves the same cost problem with a second model, a second key and a second failure mode

Three conclusions. Cursor's answer is out for a structural reason rather than a budgetary one: Genesis makes one streaming call per turn, and everything from the message cap to the SSE contract is built on that. Line numbers are out, unanimously — models miscount, and a number is stale the moment an earlier edit in the same reply changes the line count above it. Echoing the text is also a check that the model is changing what it thinks it is changing, which a number is not. And Aider's fuzzy tail is out while its exact head is in: a Levenshtein match that lands three lines off writes a broken app and reports success, which is the exact failure this feature exists to prevent.

The block

Four more verbs, because “add” is not “change”

The model has exactly one verb today — write this file — and users ask for at least four different things. Collapsing them is what forces a rewrite: “add one more theme” is an insertion, and the only way to express an insertion with a rewrite is to re-emit everything around it.

The user asks forVerbAnchorResolves to
“build me a dashboard” · “start over with a table” <genesis:file> — the whole file
“add one more theme” <genesis:append> — from = to at end of file
“put a dark-mode toggle in the header” <genesis:after>
<genesis:before>		 kept from = to beside it
“make the cards rounded” · “drop the search box” <genesis:edit> replaced from..to over it

This is the same verb set Anthropic's own text editor tool exposes — create, insert, str_replace — which is the strongest evidence available, since that is the tool claude-opus-5 is post-trained on. Three grammars cover all five: one section, two sections separated by <genesis:add>, two separated by <genesis:with>. 

add — no anchor at all, so nothing can be matched wrongly
<genesis:append path="styles.css">
.theme-dark .card { background: #111; }
</genesis:append>

add at a place — the anchor is kept
<genesis:after path="index.html">
  <h1>Contacts</h1>
<genesis:add>
  <button id="theme">Dark mode</button>
</genesis:after>

change — the anchor is replaced; an empty replacement deletes
<genesis:edit path="styles.css">
.card { background: #ffffff; }
<genesis:with>
.card { background: var(--surface); }
</genesis:edit>
Why the insert verbs are not sugar

Expressed as a replace, “add one more theme” makes the model echo the neighbouring rule twice — once as the anchor and again inside the replacement. That costs tokens, and it invites the model to paraphrase the copy it is re-emitting, silently altering code the user never mentioned. append is the cheapest op in the set: no anchor, no matching, and therefore no way to land in the wrong place.

Five verbs, two wire shapes

The authoring surface and the wire are different problems. The model needs verbs that match intent, because picking one is a judgement it makes token by token. The browser needs a single contract — this file, these lines, this text — because it has to splice into a Monaco model. So the server resolves every verb to a range before the first chunk goes out: file keeps its own frames, and all four of the others collapse to edit_start { path, from, to }, where from === to is a pure insertion and from < to is a replacement. A sixth verb would be a new grammar and no new frame.

Reusing the grammar is the point. One splitter, one hold-back bound, one chunking-invariance property — the property that caught a real bug in Slice 6 when a partial line arrived across two deltas. A namespaced tag also survives contact with the content: no realistic HTML, CSS, JavaScript or Markdown file emits <genesis:with> alone on a line, which is exactly the claim that cannot be made about =======.

What it becomes

On the server, every edit is applied to a working copy and what leaves the LLM layer is a whole-file { path, content } — the same shape a <genesis:file> block produces. That single decision is why this slice is small: path rules, the 100 KB byte cap, the 20-file cap, create-versus-merge, the single WriteBatch and the snapshot of the resulting file set are all untouched, and every invariant Slices 6 and 11 paid for holds by construction rather than by a second implementation agreeing with the first.

The turn

Where the anchor is resolved, and where it is resolved again

The hazard

A generation can run for nine minutes

The editor is read-only for the length of a stream, which closes one tab. It does not close a second device, or a PUT from another window. A patch carries a claim about what it is patching, and that claim can expire mid-flight.

Failure

One edit block in, eight ways out

Every refusal keeps the two properties Slice 6 established: the whole turn's files are refused together, and the assistant message still commits — now carrying the reason, so it survives a reload and reaches the model on the next turn.

Why no automatic repair round

Aider, Cline and Codex all feed the failure back to the model automatically, and they are right that the feedback is what makes edits usable. What they need that we do not is the automatic round trip: they are editing files the model has only seen partially. Ours was shown every file verbatim in the same request, so an exact-match failure is rare — and an unconditional second streaming call would spend on every turn what a click spends on few.

The wire

Three frames, and what the browser does with them

POST /generate is otherwise unchanged: same request, same auth, same two-channel error rule, same terminal events.

edit_start { path: string, from: number, to: number }

The find section closed and the anchor resolved. Lines are 1-based into the file as the server read it, to exclusive.

edit_chunk { path: string, text: string }

Replacement text as it streams. Trailing newlines are held back and normalised exactly as file_chunk's are.

edit_end { path: string }

The block closed. Nothing follows for that path until done, which refetches as it already does.

An edit whose anchor does not resolve emits no frames at all and no part of its content reaches any token frame — the browser never sees a change that is not going to happen.

Rendering a change you only have a fragment of

The store composes prefix + accumulated + suffix into the streaming buffer that already exists and already wins over the stored file during a stream. So an edit is a different way to fill the same slot, not a second display path. If the browser holds no content for that path it fetches it once, buffers chunks meanwhile, and splices when the fetch lands; if the fetch fails it shows the replacement alone and done repairs it.

In Monaco the edit lands through a splice — common prefix, common suffix, and the minimal range between them — applied over that range rather than over the whole document. This is the user-visible half of the whole slice: only the segments that need updating are updated, in the editor as well as in the model's output. It improves whole-file rewrites too, since a rewrite that shares a prefix now splices instead of replacing.

Slice 7 paid for the lesson that makes this a pure module with its own tests: a full-range replace per chunk is the same class of mistake as setValue — it re-tokenises the whole document for a ten-line change and moves the viewport away from what changed — and it is invisible below L5, because jsdom computes no layout.

Proof

Where the risk lives

Thirty-eight acceptance criteria, distributed by the level that can actually prove them. The shape of this chart is a design statement: almost everything decidable was pushed into pure functions.

What no test here can prove

The edit-versus-rewrite policy is a prompt, and this repository's fixtures are hand-authored: they say what the model is told, never what it does. Two hand-checks against the real model are therefore in the definition of done rather than in the suite — that a second prompt produces edit blocks rather than whole files, and that a third prompt within five minutes shows a non-zero cacheReadInputTokens.

RiskMitigation
The model does not adopt the format. A model that keeps writing whole files leaves the slice inert. The worked example sits in the cached prefix beside the file-block example that already works. The hand-check is required before merge — and the format is the variable, not the architecture.
Anchor failures are routine, making refusals the normal experience. Transcript feedback plus Retry is the cheap repair. If the hand-check shows failures are common, the automatic round-trip becomes the next slice rather than a guess made now.
A file's own content contains a delimiter line. The same exposure </genesis:file> has carried since Slice 6, mitigated by the same thing — and it is why ======= was rejected.
The splice makes the editor worse, invisibly. A pure module with its own tests, plus a real-browser assertion about screen positions rather than about the function.
Moving the project state into a user message regresses quality. Documents-before-query is the recommended placement for long context; the change is four lines to revert, and the hand-check is against real generations.
PR size — the edit protocol and the request reshaping in one branch. One subject: the cost of a follow-up turn. The caching half is four files and mostly tests, and it lifts out cleanly if review asks.
