01The shape of one request

Everything above the breakpoint is byte-identical on every generation this project ever makes; everything below it changes per turn. That single line is why the cheat-sheet goes in system and the project's files do not.

02What a generated app can reach

The prompt teaches exactly one function and not a single URL. Everything a request needs to become real — the origin, the token, the version header, the location — is added on the far side of a boundary the generated code cannot see.

03The hazard: a file cut in half

This slice's whole reason for a budget is also its worst failure mode. Sending part of a file is not a smaller version of sending the file; it is a different, worse thing.

The second hazard, which needs one line rather than a figure

Trimming a transcript from the oldest end lands on an assistant turn roughly half the time, and the Messages API requires the first message to be user. Untreated, that is a 400 the user reads as “generation failed” — on long conversations only, which no fixture-sized test reaches. 04The contract this slice defines

Slice 9 names the function; Slice 10 implements it. Both halves are written here so the two cannot drift apart between now and the preview.

hl(method, path, payload?)

The only way a generated app reaches HighLevel. Injected by Genesis into the page that runs the app.

Payload
Query parameters on GET; JSON body on POST and PUT.
Resolves with
HighLevel's own JSON body, unwrapped — no envelope, no renaming.
Rejects with
message (a sentence to show), status, code.
Never send
locationId, an Authorization header, or an absolute URL.
// taught verbatim, in the cached prefix
const page = await hl('POST', '/contacts/search',
                       { pageLimit: 20 })
const events = await hl('GET', '/calendars/events',
                       { startTime, endTime, calendarId })

What the cheat-sheet is made of

Rendered at module load, so the allowlist and the prompt cannot disagree.

  • 12 routes, rendered from HL_ROUTES — contacts, conversations, calendars. The flagged message-send row is filtered out.
  • Per-surface notes, only where they are verified: /calendars/events takes epoch milliseconds, and ISO-8601 returns an empty success rather than an error.
  • Response shapes — one trimmed record per surface, every field name asserted against a recorded fixture.
  • 12 error codes, rendered from the proxy's own copy table, with the instruction to catch and show message.
  • One hard rule: use the list endpoint, never one request per row. The burst ceiling is 100 requests per 10 seconds.

05Where a failed call ends up

One hl() call, every exit, and what the person using the generated app actually sees. This is the fan the prompt teaches the model to handle — the alternative is an app that renders a blank list and says nothing.

06Where the risk lives

Twenty-eight acceptance criteria, and twenty-five of them are pure functions. That is a design statement, not an accident: almost everything this slice decides is a string being assembled, and the one thing it cannot test at all is the thing it is for.

07Risks

#RiskMitigation
R1 The slice is judged on model behaviour no automated test here can observe. Stated rather than papered over. Three manual checks in the definition of done, with the generated code pasted into the PR. The bidirectional allowlist tests at least make “the model was told something false” impossible.
R2 A truncated file would silently rewrite code the user never touched. Whole files or none, with omissions announced. AC-17 asserts the negative — no fragment of an over-budget file appears anywhere.
R3 A leading assistant message is a 400, and it only appears on long conversations. The guard lives in the same function as the trim, driven by a transcript built to land there, and again under the emulator through the fake's new __context marker.
R4 /contacts/search's filter grammar is still unverified, and it is what a contact dashboard most wants. Teach the verified shape only, and tell the model to filter a page in the browser. A less clever app beats a 400 in the demo. Named as a README follow-up.
R5 The cheat-sheet is a second place the allowlist can be wrong — and a wrong line is worse than a missing one. Rendered data, not prose, checked in both directions. The residual exposure is the hand-written per-surface notes; response shapes are tied to recorded fixtures.
R6 Effort high lengthens the pause before the first token, on the surface whose demo value is tokens appearing. Keep-alives cover an idle stream and the Generating… badge makes the pause legible. high rather than xhigh is the conservative half of the trade; the sweep is a named manual check.
R7 Prompt injection through a project's own files. Self-injection only — files are uid-scoped and reach the prompt only for their owner. The controls that matter are downstream and unaffected: the op set is refused whole, and the allowlist decides what any generated code can reach regardless of what it was told.
R8 One more Firestore read and one more failure mode on the generation path. Capped at 20 documents and executed before the flush, so its failure is an ordinary JSON 500 rather than a mid-stream error frame.
