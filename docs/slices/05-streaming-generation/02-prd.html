Slice 05 · design companion

One channel, one ending

A generation is a single HTTP response that is opened once, written to in frames, and ended exactly once. Two things follow, and this slice is mostly about them: the instant that response opens, the ability to answer with a status code is spent — and the instant it closes early, something has to have been saved.

event: boundary

What is on which side of the line

This slice introduces the first thing in the product that costs money to use, and the first secret that is not an OAuth credential. The browser gains no new power at all: it holds its own two tokens and nothing else, and the collection it would need to read is still closed to it outright.

event: sequence

One turn, thirteen steps

A turn is two requests, not one — the prompt is made durable before the expensive half starts, which is the whole of F8.2. Watch the orange band on the left: the placeholder bubble is born when the stream opens and destroyed when it ends, and it is the only piece of state in the slice with a lifetime shorter than the request.

event: hazard

The recovery path is the one that breaks

A transcript whose last message is an assistant message is, to the Messages API, an assistant prefill — and prefill returns a 400 on claude-opus-5. That shape is not exotic. It is exactly what an interrupted turn leaves behind, so without the mitigation the request that fails is the retry.

and its consequence

Dropping trailing turns can leave nothing. A project whose messages are all assistant echoes assembles to an empty array, which the API also rejects. That is answered by us instead, as 400 empty_context, before a single token is paid for — the one place in this slice where a refusal is cheaper than the alternative and also more honest about the cause.

event: error

One request in, ten ways out, and a line down the middle

flushHeaders() is the boundary between the two error channels, and every refusal that can be decided cheaply is decided on the left of it. Above the dashed rule, a failure is a status code and a JSON envelope. Below it, the status line is spent: a failure is an error frame on a 200. One exit writes no frame at all.

Where the risk is, read off the test levels

Forty-four acceptance criteria. The distribution is a design statement, not an accident: most of this slice's danger is in pure logic that can be tested without a network — two parsers, a context builder, an event mapper — and almost all of the rest is at the emulator boundary, where the two error channels and the disconnect can be exercised for real.

event: risk

What could still go wrong

#RiskMitigation
R1 A trailing assistant message is a prefill, and prefill is a 400 on this model. The shape arises on Retry and on every Slice 4 project. The drop rule, asserted at L1 over synthetic transcripts and at L4 by streaming, interrupting and retrying for real.
R2 A generation may outlive what Hosting and Cloud Run in front of it tolerate — invisible from the emulator, like the missing index two slices ago. Headers flushed first (proven in Slice 0), keep-alive comments, effort: low. The documented fallback is pointing the SPA straight at the function URL. Verified by hand at deploy, and named in Slice 13's checklist rather than pretended into a test.
R3 The Vite dev proxy sits between the browser and the stream locally, and Slice 0 only proved the Hosting path. A buffering proxy makes every local demo look broken. A fresh-clone check in the definition of done, plus the e2e progressive-text assertion — which runs through that proxy, so full buffering fails a test instead of puzzling a human.
R4 The client parser is handed frames split at arbitrary byte offsets. The naive version passes every hand-written test, because hand-written chunks are whole frames. Its own module, driven from a chunk sequence, with L1 cases that split mid-field-name, mid-JSON and mid-terminator.
R5 Generation costs money and the only limits are a verified account, attestation and the 200-message cap. Bounded rather than solved, and named: the cap makes a project's spend finite; per-user rate limiting is stretch S4.
R6 Two failure channels, one of which cannot use a status code. Throw after the flush and the response is unparseable; flush too early and 404 becomes unsayable. The boundary is explicit and the handler is ordered around it; both channels are asserted at L4.
R7 truncated is new on documents Slice 4 already wrote. Required, it would silently empty every older transcript. A parse default, with an L1 case over a Slice-4-shaped document and an L4 case that seeds one and reads it back.
R8 output_config.effort and the thinking parameter are recent; the installed SDK's typings may lag. The tempting fix is a cast, which this codebase forbids. The plan pins the SDK version and, if a parameter is untyped, passes it the documented way with a comment — never an as. A typecheck failure cannot be missed.
R9 Deleting the echo turns Slice 4's green tests red, which reads like a regression. Recorded with its scope: the e2e assertion becomes a streamed-reply assertion in the same file, and the echo unit cases go in the same commit as the behaviour replacing them.

The acceptance criteria, the test matrix and the decisions table are the contract, and they live in 02-prd.md beside this page. This companion exists only for the four things prose makes a reader assemble in their head: the boundary, the sequence, the hazard, and every way out.
