The way out

Eleven slices each built their own loading, empty and error states. Read together for the first time, they are almost all there — so this slice is not about covering failures. It is about the two places the plan still has no door on it, and about saying the same thing in one voice everywhere else.

The acceptance criteria, the decisions and the test matrix live in 02-prd.md, which is the contract. This page draws the four things prose makes you assemble in your head: every exit from a failed call, the one hazard that has no exit today, which surface a notice is allowed to use, and where this slice's risk is tested.

  • 19surfaces audited, each for loading, empty and error
  • 0missing states found — the definition-of-done line is already met
  • 19hand-rolled placeholders across 10 components, becoming one primitive
  • 2failures that still speak in a language that is not ours

The failure fan

One entrance — any authenticated call the SPA makes — and every exit it can take. The question each door answers is not what went wrong but what does the person looking at the screen do next, which is the only question F8 actually asks. Eight of these doors are already hung. Two are this slice's work.

  • no answer yet
  • they stay, and can act
  • the app moves them, and brings them back
  • transient notice, nothing to act on
  • stranded — told something true, given nothing to do

The hazard: a session that ends while the tab is open

This is the one failure in the app with no exit, and it is worth drawing as a comparison because the before side does not look like a bug. Every panel says something true. Every panel offers a Try again. The user is simply on a merry-go-round: each retry mints the same dead token, gets the same 401, and prints the same sentence. Nothing on screen ever mentions signing in, and nothing navigates.

Which surface may say what

Adopting sonner is the decision most likely to spread, so it ships with a rule rather than with taste. Two questions decide the surface, and they are the only two: is there an answer yet, and must the user do something about it. The rule is what makes a new runtime dependency a two-call-site change instead of a rewrite of eighteen error surfaces.

Where the risk is tested

Twenty acceptance criteria, twenty-four test rows, and two empty levels. The emptiness is a claim rather than an omission: this slice adds no collection and touches no Cloud Function, so an L3 or L4 row would mean something had been added that the decision said would not be. The definition of done makes git diff main…HEAD --stat prove it.

Risks

Carried from 02-prd.md, where each has its mitigation in full
#RiskWhat holds it
R1 vue-sonner needs its stylesheet imported, and a missed import ships an invisible toast that every test still passes — the tests assert the call, not the pixels. The definition of done includes seeing a toast with human eyes during the manual walk.
R2 Swapping nineteen placeholders is nineteen chances to change a layout. Monaco is the sharp one: its height chain is flex the whole way down since Slice 7, and it measures its container. Sizing utilities are kept element for element; only the pulse and colour classes change. Slice 7's “real height at both layouts” e2e is the backstop.
R3 The sign-out hook is a global side effect on a shared module. A wrong branch signs users out on a transient failure. Figure 1's fourth row: the branch is on code, never on status. AC-13, AC-14 and AC-15 exist to pin the three ways it could over-fire.
R4 The hook makes apiClient stateful, so a test that registers it can leak into the next. Registered in main.ts, reset per test, and the unregistered default is asserted to be a no-op.
R5 AC-1 could balloon if the audit's L2 coverage is thinner than it reads. The testids in the audit table were read out of the source at 94bcc1f, not guessed. A row needing more than a test becomes an out-of-scope line.
R6 The e2e forces a 401 with page.route, not a real revocation — the Auth emulator will not invalidate an unexpired ID token. Said plainly in the test's own comment. The server half is covered by requireUser's existing tests; this walk's subject is the client's reaction.
R7 This is the last slice before deploy, and a regression in it is a regression on every screen at once. It touches frontend/ and tests/e2e/ only, the swaps are mechanical, and the full suite is the gate.

What this slice is not

Nineteen items were handed forward to “Slice 12's audit” by the reviews of Slices 7, 8, 10 and 11. Four are in — the skeleton, the toast, the announcement, and a reader for detail. The other fifteen are re-homed in the PRD's out-of-scope table with a reason each, and the reason is nearly always the same one: a structural refactor or a security-grammar change placed beside a uniformity pass makes one diff out of two changes, which is the shape a review misses things in — the very argument Slice 7 used when it deferred the first of them here.
